# 特殊功能有效性 / 健壮度 / 性能回顾（2026-08-19）

范围：工作流里「不是普通键位」的特殊能力。判定口径：设计意图是否还成立，而不是代码在不在。

## 0. 先回答：启动 Agent 的猫是不是失效了

**是，对全屏 TUI Agent（Grok / Kimi / Agy / Codex）基本失效。**

设计意图：盖住「页签已开、Agent 还没画出第一帧」的僵硬空屏。  
现行实现：新开 PowerShell → `Console.Clear()` → 画 **1 帧静态猫** → 立刻 `& exe`。

注释与代码已经打架：`Get-AgentLaunchArgv` 仍写「splash 让 2–5s TUI 启动不再是黑页」；`Get-AgentSplashScript` 写「no Clear，猫一直待到 TUI 接管」；`launch.lua` 写「帧会留在屏幕上直到 CLI 启动完」。模板第一行却是 `try { [Console]::Clear() }`。承诺的是封面，交出的是闪一下再交权。

失效链：

1. 包装脚本自己先 `Clear()`，猫只存在于 exec 之前那几十毫秒。
2. Grok/Kimi/Agy/Codex 进 TUI 时会再清屏或切备用缓冲区，猫被擦掉。
3. 之后 2–5 秒是 **Agent 进程自己的冷启动**，控制台归它，工作台无法再画猫。
4. 用户看到的是：猫闪一下 → 黑屏数秒 → TUI。和「盖住启动过程」相反。

另外还付了约 170ms 的 PowerShell 宿主税，换不来那几秒封面。

DeepSeek 是行式 REPL，启动前又故意再 Clear 一次，避免猫残在对话上方——这里猫不是封面，是必须拆掉的装饰。

**Init 读列表的猫没有失效。** 那条路径工作台仍占有控制台，读会话/探测时猫跟着真实计数走，属于「看着干活」而不是「先播完再干活」。

结论：猫只适合 **我们还握着屏幕的阶段**（Init 加载）。Agent 启动后屏幕所有权交给外部进程，再画猫没有物理手段维持。硬要盖住 2–5 秒，只能另做一层（例如独立指示窗格，等子进程有输出再拆），不能靠当前「画一帧再 exec」。

## 2. 分项说明

### 2.1 Init 猫（有效）

- 价值：打开 Init 时若静默 1–2 秒，会像死机。有猫 + 真实 `当前/总数`，符合 D-017。
- 健壮：重定向宿主跳过重绘，避免测试假巨行。`Reset-Screen` 会先刷空白，仍有极短空窗。
- 性能：不 Sleep 等动画；66ms 节流。探测子脚本那 0.2–0.5s 若条不更新，观感仍像卡住。
- 不要做：不要把文件夹体积扫描请回来给猫「更多帧」。

### 2.2 Agent 启动猫（意图在，机制不成立）

- 价值主张成立，**实现物理上盖不住**外部 TUI 的清屏与加载。
- 健壮：零 Sleep 避免再变成效率税；DeepSeek 清残帧是对的。
- 性能：PowerShell 包装对原生 `.exe` 是纯损耗（本机约 170ms），换不来封面。
- 可选方向（需另批，本回顾不施工）：
  - A. 原生 `.exe` 直 spawn，去掉启动猫（F6 曾经如此，最快）。
  - B. 接受「猫只表示正在交接」，不承诺盖住冷启动。
  - C. 另开窄指示窗格，检测到 Agent 进程/输出再关（重、易抖）。

推荐默认 **A + 对用户说实话**：启动黑屏是 Agent 自己的，不是工作台没做猫。**2026-08-19 已按 A 施工（D-018）。**

### 2.3 开放探测

- 价值：没有 Grok 的机器、新装 CLI、F8 平权，都靠它。R0 门禁绑在 `validate_project` 上是对的。
- 健壮：命名参数、`PositionalBinding=$false`、缓存不用 `List[object]`。仍依赖「调用方不 splat」。
- 性能：20s 文件缓存让第二次 Init/F8 明显轻；首次仍要扫 PATH。不要为了再快 100ms 退回白名单。

### 2.4 Init 两步流

- 价值：这是日常主路径，比 F8 重要。
- 健壮：e2e 锁「AGENT 行数 = 探测数」，防再出现「界面还在、一家都没有」。
- 性能：列表脏标记后按键不重扫，这是 08-13 真正有效的优化。

### 2.5 F8 修理舱

- 价值：解开「Init 死了就不能用 WZ 修 WZ」。cwd 在安装根 `repair\`，符合「用户不迭代源码、只修安装」。
- 健壮：不跑 bootstrap；`q` 取消；标题清洗；JOURNAL 追加。页签曾被第三列盖成 Agy，已改绘制规则。
- 性能：进舱要跑一次探测（与 Init 同级）。可接受。不要在 F8 里扫会话历史。

### 2.6 页签 / HUD

- 价值：多任务时只看标题要能分清「哪个项目、哪个模型」。
- 健壮：曾经用 desk-roots 第三列冒充现场 Agent，属于身份契约错误，不是性能问题。
- 性能：好。Init 页签探测有 30s 缓存，不要再对每个页签做进程快照。

### 2.7 已证明不值得的优化

- 整树测文件夹体积（Act\*）：拖死 Unity 一类目录，相对大小还不准，已拆除。
- 多帧 Sleep 猫：375ms 纯税，已拆。
- 未提交加固被覆盖：流程问题，不是功能问题。

---

## 3. 总判断

工作流里真正值钱、也真正站得住的，是：**任务/模型解耦、开放探测、脏标记不重扫、F8 不依赖 Init、页签身份分槽。**

猫只在 **Init 自己读盘** 时成立。  
**启动 Agent 的猫没有完成设计承诺**——不是没画，是画完立刻失去屏幕，后续黑屏属于 Agent 冷启动，工作台盖不住。继续加帧或加 Sleep 只会再变成税。

D-018 已落地：原生 `.exe` 去掉启动包装，「黑几秒」按 Agent 就绪时间理解。
