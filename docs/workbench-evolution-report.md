# WZ_AiStarCube 功能提升分析报告（2026-08-07 ~ 2026-08-19）

本报告按时间线完整交代这个工作流工具从骨架到蒸馏发布的演进前因后果，数据全部来自 DECISIONS.md 状态事件与实测记录。

---

## 一、原点与目标

个人 AI 工作台：以 WezTerm 为载体的多 Agent CLI 调度台。产品路线（D-002）：先把 live 工作台做到作者满意，再封装为 skill。核心设计理念（用户多轮确立）：**Agent 平权**——开展任务时用户有充分的 Agent 切换选择，每个 Agent 都是平权选项。

## 二、演进五阶段

### 阶段 0 · 骨架与门禁（08-07 ~ 08-09）

- 确立命名（D-001 WZ-AiWorkBench）、workbench-first 路线（D-002）、项目名与硬门禁（D-003：弱路径不得当项目根、创建流程路径冻结）。
- 多模型交接设计（D-004）：同一任务可被不同 agent 接管；grok/kimi 会话扫描与 resume 链路落地（F-011/F-012）。
- 键位精简化：F1 帮助/F3 新建/F4 关窗格/F6 desk/F7 Explorer/F9 项目；修复 WezTerm 配置加载 yield 炸弹（`load guard` 由此诞生）。
- **起点形态**：grok/kimi 两家、Init 面板初版、Leader 键（Alt+z）。

### 阶段 1 · 平权与交互统一（08-13）

- **D-008 agent 平权选择**：Init 两步流同构（两步都支持数字+Enter）、F6 平权选择器（InputSelector，默认=路由 agent，Esc 零 spawn）。
- **Init 卡顿三连修**：① 行缓存+脏标记（原每键全量扫会话目录）；② 渲染器 v1（局部坐标更新）实测更闪当日推翻；③ v2 整帧覆写仍不达标 → **D-009 终局：静态屏+行输入**（Read-Host 行语法，状态转换才整屏重绘一次）。教训：PS 5.1 + ConPTY 下逐键重绘不可救。
- **序号制式统一 + 阶段高亮 + 行走猫读条**：两区序号芯片 `[n]` 同位同构、亮黄=激活步骤可输序号；5 行行走猫进度条诞生。
- **D-010 组合直启**：默认视图封顶 9 行（任务号恒个位），`<任务><agent>` 两位数组合一次启动。
- **D-011 页签污染门禁**：spawn 改名严格 pane-id 解析 + 自指 guard + 调试日志。
- 右缘爆格子根治（列宽结构性重算 + 硬截断）。

### 阶段 2 · 生命周期与色彩标准（08-14）

- **加固审查 R1（P-008/D-006）+ R2（P-011）**：两轮系统性审查，M/L 级问题全修（超长数字溢出、空环境变量护栏、向导 spawn 用全路径、EOF 防死循环等 14 项）。
- **D-012 启动即关**：Init = 短命启动器，启动成功即关原页签，结构性消除页签污染（放弃四层脆弱的"钉住"方案——其中 user-var 方案事后查明从未被加载）。
- **性能根治**：pane_is_init 的进程快照税（周期性卡顿）→ 预过滤+30s TTL；启动 0.6s 死等 → 200ms。
- **F-014 DeepSeek 接入**：社区 CLI（无官方），四平权；codex 探测补 WinGet 落点。
- **splash 猫全 agent 平权**：grok/kimi 以外的 agent 启动也有猫猫读条；启动包装统一。
- **D-013 色彩标准**：亮黄=全局唯一「可输入」可供性色（索引芯片+输入前缀两类），其余禁用；信息=Cyan/White，成功=Green，错误=Red，装饰=Magenta，边框=DarkGray。
- **D-014 单击开链接恢复**：查明"不能点"非回归而是 08-09 防误开的硬化；用 `CompleteSelectionOrOpenLinkAtMouseCursor` 恢复单击 + launcher 扩展结构性去链接（.cmd/.exe 永不生成链接）替代"禁交互"。

### 阶段 3 · 开放化与蒸馏发布（08-15 ~ 08-16）

- **D-015 四步向导**：CLI 与 agent 合并为单一选择（身份不可拆分），位置手输仅留 `[0]`（`[9]` 历史错误清除），PowerShell-only 显式 `shell` 不伪造 grok。
- **D-016 开放式探测（架构级跃迁）**：`agent-discovery.ps1` 元数据驱动、零产品白名单、不执行候选——npm/Python 元数据 + exe 版本资源 + `*.wz-agent.json` + 用户级 `app\bin` 静态能力声明 + 本地 TSV 逃生舱；合并进程与持久化 PATH。Init/F3/F6/安装器/侧栏/open-project 共用同一清单。删除 Grok 专属 Dashboard 与启动菜单产品项。COMMAND 三行固定网格。
- **D-017 Windows-only 蒸馏发布**：四原则（轻量/稳定/高性能/全面平权）对抗性审查；猫猫读条改真实总进度（可计数）/不定动画（不可计数），禁止伪造百分比；原子写盘与安装哈希校验；GitHub 改名 `WZ_AiStarCube_win`。
- **Codex 版本倒挂修复**：低版本 CLI 续聊高版本会话的 -32603 错误 → 版本门禁（已知低版本阻止 spawn 并提示升级）。
- **PATH 漏探修复**：安装器写的用户 PATH 对长寿命进程不可见 → 探测器每次合并注册表持久化 PATH。

### 阶段 4 · 性能实测与稳定化（08-17 ~ 08-19）

- 本机部署蒸馏版；codex 本机登记（local.tsv 逃生舱首次实战）；安装器 known-folder 加固。
- **Grok 性能三轮**：探测慢根因=136MB 级 exe 整文件扫描（能力词在 119MB 处）+ `File.Replace($null)` 抛错致指纹缓存永不更新 → 原子缓存替换、8MB/400ms 扫描封顶、路径形态接纳、20s 清单缓存；启动包装去 375ms 动画税、原生 exe 直 spawn、`-NoProfile`。
- **归零事故与双层修复**（I4/I4b）：splat 位置绑定错绑 + `List[object]` DLR bug，双双静默；修复 + `test-init-e2e.ps1` 用户视角断言 + AGENTS.md 施工红线七条 + `docs/agent-incident-review.md`。

## 四、关键转折点的因果链

1. **「闪烁」三次失败 → 设计理念收敛**：逐键重绘（v1/v2 皆败）教会项目「PS 5.1 终端不做局部更新」，D-009 静态屏是唯一稳态解——后续一切 UI 都建立在此认知上。
2. **「页签污染」三连 → 结构性思维**：从修写入（D-011）到修显示（钉住，证明不可维系）到消灭目标（D-012 启动即关）——能消灭故障源的就不修补故障。
3. **「grok 专属残留」用户反馈 → D-016 开放探测**：从四家平权升级为 N 家开放，产品名彻底退出候选资格判定；resume 降级为可选适配器。这是本项目最重要的架构决策。
4. **「又不能点了」→ D-014**：查明非回归而是旧硬化误伤，用结构性护栏（launcher 去链接）换回交互，而不是二选一。
5. **「AGENT 归零」→ 门禁时代**：splat/DLR 双静默 bug 证明「单测绿≠系统绿」，催生 e2e 用户视角断言 + 红线七条——从"靠自觉"转向"靠门禁"。

## 五、当前可靠性与剩余风险

**验证基线**：六~七套自动化回归全绿、BOM/parse 强制、live↔镜像哈希对拍、ls-fonts/load guard 真实加载验证、validate_project + readiness 双收口。

**留观察项**：L2-4（desk.lua 对 node 版 deepseek 识别）、L2-6（deepseek 恒 -NoExit 不对称）、L2-8（splash 贴底漂移）。
**待验收**：P-006 验收清单待批准升格 D；F6 三栏形态待定夺；DeepSeek 402 余额待充值。
**流程级剩余风险**：多 Agent 接力施工的交接协议尚未落地（报告 `agent-incident-review.md` 第六节）；verify-gate 单入口与 pre-commit 钩子待批准。

## 六、结论

十三天内，该工作台从「grok/kimi 两家的个人脚本」演进为「开放探测、行为门禁、Windows-only 发布的蒸馏产品」。演进的主线不是功能堆叠，而是三次认知升级：**交互上**接受终端现实（静态屏）、**架构上**消灭故障源而非修补（启动即关、开放探测）、**工程上**用门禁替代自觉（红线+e2e）。三次事故的代价全部转化为了可复用的回归资产。
